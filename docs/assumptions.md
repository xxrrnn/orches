# Assumption Register

Assumptions are baseline inputs that are not directly stated by the paper.
They remain visible until confirmed by an official artifact or replaced by a
calibration. Main evaluation runs must record the active assumption IDs.

| ID | Assumption | Reason | Validation or sensitivity requirement | State |
|---|---|---|---|---|
| `A-HW-001` | Paper's 32 GB PIM maps to a 32 GiB Ramulator2 address space. | The paper does not define decimal/binary capacity semantics. | Report the unit mapping and test any trace near the capacity boundary. | Open |
| `A-HW-002` | `HBM3_8Gb_2R` with 32 channels is the PIM organization. | It preserves AttAcc's preset and doubles AttAcc's 16-channel baseline, simultaneously realizing 32 GiB and 2048 banks. | Compare against an official ORCHES artifact if released; retain channel-count and organization sensitivity. | Open |
| `A-GPU-001` | NVIDIA peak core/frequency specifications bound the AGX Orin analytical model. | ORCHES names the module but does not disclose achieved throughput. | Keep peak-derived rates explicitly analytical, run utilization sensitivity, and compare with an optional Orin-calibrated profile; never label peak as measured throughput. | Open |
| `A-PIM-001` | One configured GEMV lane represents one multiplier-plus-adder datapath per bank. | This is the most direct representation of Sec. 4.1 wording. | Validate command issue and accumulation semantics with PIM microbenchmarks. | Open |
| `A-MODEL-001` | Public Qwen/RLHFlow PRM architectures proxy the paper's custom `*-PRM-Tuned` checkpoints. | The paper does not disclose exact tuned checkpoint revisions. | Replace proxies during trace collection and report any architecture mismatch. | Open |
| `A-CAL-001` | No achieved AGX Orin compute rate, launch overhead, or effective bandwidth is available yet. | The current host has no target GPU and the paper omits calibration details; Sec. 5.1 instead says to retain AttAcc's previously validated model and unit costs. | Publish `paper_method` results with analytical/inherited fields and sensitivity; add a separate `orin_calibrated` result when target hardware is available. | Open |
| `A-GPU-002` | The `paper_method` profile applies AttAcc's fixed 0.8 compute and 0.85 off-memory-bandwidth utilization factors after substituting explicit AGX Orin peak parameters. | ORCHES says it retains AttAcc's validated GPU model but does not release its Orin frontend configuration. | Compare utilization-factor sweeps and an Orin-calibrated profile; do not tune factors to the paper's final speedup. | Open |
| `A-TRACE-001` | Logical per-token readiness, not collector wall time, drives T2B replay. | A model trace may be collected on a 5070 Ti and replayed against Orin; absolute collector time would mix hardware domains. | Preserve raw wall time only as diagnostics and test that replay is invariant to a uniform rescaling of collected timestamps. | Open |
| `A-TRACE-002` | Trace sizes and live KV are derived from exact model token IDs, masks, KV materialization, and ordered selection lineage; character counts and fixed winner assumptions are forbidden. | Chat templates, special tokens, final-token cache semantics, multi-beam top-k, and pairwise tournament pruning can all make text-length or simple cumulative-token proxies incorrect. | Cross-check every next-step input against retained parent token IDs; test width 4 with nontrivial winner order and beam size greater than one. | Open |
| `A-VISION-001` | LLaVA-CoT commit `8983878f7b7fa3fe72232fa656be0b2ac41c6338` is the closest public paper-era executable proxy; its hard-coded stage-beam width will be exposed as 2/4. | The frozen LLaVA-o1 checkout is a redirect and ORCHES does not disclose the exact pipeline revision. | Retain the source patch and compare behavior with an official ORCHES artifact if released. | Open |
| `A-VISION-002` | MathVista short/medium/long groups are tokenized-question-length tertiles over the frozen evaluation split. | ORCHES reports three groups but no boundaries. | Store tokenizer, thresholds, tie rule, and per-bucket counts; report sensitivity to alternative equal-width buckets. | Open |
| `A-T2-001` | Candidate path scores use an explicitly selected mean, minimum, or last-score aggregation. | The paper describes history replacement but does not disclose the full score aggregation function. | Freeze the chosen method per experiment and run all three as sensitivity points unless author code resolves it. | Open |
| `A-T1-001` | Small/medium/large branch-width boundaries are supplied by calibration rather than hard-coded. | Sec. 4.2.1 defines three regions but does not publish exact transition widths for every model and bandwidth. | Derive boundaries from frozen operator calibration and save them in every evaluation configuration. | Open |
| `A-T2-002` | The minimum pipelined-prefill token count and per-token verifier rates are explicit calibration inputs. | Sec. 4.3.2 requires enough arithmetic intensity to utilize the GPU but gives no universal threshold. | Sweep the threshold per PRM and freeze the selected calibration point before evaluation. | Open |
| `A-T2-003` | T2B replay maps logical policy-token readiness to incremental small-PRM work; full verifier input tensors size final calls, but cross-tokenizer streamed-input alignment is not inferred. | The paper does not publish how policy-token completion maps to incremental PRM tokenization, and collector wall time cannot be reused as Orin timing. | Record verifier-position readiness in the real collector, test same- and cross-tokenizer model pairs, and replace this mapping before checkpoint-exact evaluation. | Open |
| `A-T3-001` | The controller address cache is fully associative with deterministic LRU replacement and an explicit entry count. | Sec. 4.4 states that one cache is shared across banks but omits capacity, associativity, and replacement policy. | Sweep entry count and replacement policy or replace them if an official artifact is released. | Open |
| `A-T3-002` | Address-cache SRAM and DRAM lookup latencies are supplied independently. | The paper gives only an order-of-magnitude SRAM/DRAM comparison. | Replace with CACTI and Ramulator calibration; retain hit-rate and latency sensitivity. | Open |
| `A-T3-003` | `memory_for_reasoning` is the allocated reasoning high-water span, excluding immutable model weights. | Sec. 4.4 defines beta as holes over memory for reasoning but does not define the denominator boundary. | Report both live bytes and high-water span; compare alternative total-capacity normalization. | Open |
| `A-T3-004` | Shared-KV buffer capacity, compaction bandwidth, transaction size, and optional beta threshold are explicit experiment inputs. | The paper reports 12% area and 0.12% runtime overhead but not the underlying hardware sizes/rates. | Calibrate buffer/transaction values and run interval 3/4/5 plus beta-threshold sensitivity. | Open |
| `A-BASE-001` | ORCHES-A/B/C retain T3 while T2 is disabled. | Sec. 5.3 explicitly disables T2 and changes scheduling, but does not state that the memory-structuring hardware is removed. | Report this switch matrix and run a T3-off sensitivity if its measured 0.12% overhead affects conclusions. | Open |
| `A-ENERGY-001` | AttAcc's bank-level SRAM pJ/byte coefficient is provisionally applied to the ORCHES address cache and shared-KV buffer. | ORCHES inherits prior-work unit energy but does not publish separate cache/buffer coefficients. | Replace with CACTI/synthesis values in M4B and report inherited versus calibrated energy. | Open |
| `A-AREA-001` | No numeric ORCHES cache/buffer area is accepted until the baseline die and 12% denominator are identified. | Sec. 5.5 reports 12% buffer area overhead without a component table or explicit denominator. | Store component mm2, source, and denominator; compare the resulting fraction with 12%. | Open |
| `A-DUPLEX-001` | Duplex CSV activity energy is summed over `iter_info=1` rows and request latency is the mean of `type=e2e` rows. | The native schema mixes iteration and request-completion records. | Validate aggregation against a controlled native run and retain raw CSV with every result. | Open |
